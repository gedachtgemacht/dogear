# Documentation

- Start with what it is in one sentence, then **how to run it** in the first screen: the exact commands, copy-pasteable.
- Then: requirements, configuration (table of options with defaults), usage examples with real output, how to run tests, project layout (only if non-obvious).
- Write for the reader who has 2 minutes. Short sentences, concrete nouns, no marketing words, no emoji.
- Every command must have been run by you. Do not document features that do not exist.
- Keep a **Limitations** section: what is not supported, known issues.
- Update docs in the same change as the code; stale docs are worse than none.
